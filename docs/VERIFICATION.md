## 2.1.2 提醒规则回归

- 保存新时间后，当天已确认的对应时段重新进入待办；新时间未到不提前，已过则立即进入待办。
- 上下班独立，多次修改及改回旧时间均重新触发；未确认期间连续修改只使用最后保存时间。
- 相同时间、音效或音量修改不触发新提醒，重启后沿用保存的标记。
- 验证跨天修改保留历史补提醒、周末不产生新项，以及重复点击不重复归档。
- 新设置或再次确认写盘失败时，生效设置、确认文件和内存状态均未前移。

## 2.1.0 已有界面回归

| 场景 | 操作与观察 |
| --- | --- |
| 浅色设置 | 原生玻璃面板、时间、音效、开关、音量和保存按钮完整显示 |
| 音量拖动 | 实际鼠标拖动从 100% 到约 51%，标签实时变化 |
| 设置保存 | 修改时间、Glass 音效、渐强开关和音量，JSON 文件与重新打开的控件一致 |
| 保存后关闭 | 再保存音量 75%，文件为 0.75；窗口状态为 settingsVisible=false、reminderWindows=0 |
| 非法时间 | 上下班设为同一时刻，显示“未保存：上班时间须早于同一天的下班时间。”；仍可继续操作 |
| 实例占用 | 同一目录持有第二个文件锁，设置显示行内冲突提示；保存失败原因可见，原设置未被覆盖 |

| 提醒与设置切换 | 两个显示器的提醒在打开设置后变为 0，关闭设置后恢复为 2 |
| 退出 | 测试副本退出后释放锁，无测试进程残留 |

复验命令：

```bash
bash test.sh

bash package-dmg.sh --no-build
bash Tests/dmg.sh dist/AttendanceReminder-2.1.4.dmg dist/AttendanceReminder.app
bash Tests/interface-preview.sh /absolute/test-directory settings
bash Tests/interface-preview.sh /absolute/test-directory conflict
bash Tests/interface-preview.sh /absolute/test-directory reminder dark
bash Tests/interface-preview.sh /absolute/test-directory due
bash Tests/interface-preview.sh /absolute/test-directory confirmed
bash Tests/interface-preview.sh /absolute/test-directory rescheduled
bash Tests/interface-preview.sh /absolute/test-directory both
bash Tests/interface-preview.sh /absolute/test-directory background
```

界面测试程序不随正式应用分发。`conflict` 模式故意保持文件锁占用，用于验证错误后的交互；最多运行 5 分钟。`due`、`confirmed` 和 `rescheduled` 在工作日 23:00 前运行，首次启动时把上班设为下一分钟，分别创建未确认、已确认和确认后重设时间的样本。其状态目录内记录及同级 `status-*.json` 均为测试数据；状态文件包含窗口数量、标题、设置溢出高度、系统静音提示，以及声音是否成功进入播放状态；`transitions-*.json` 保留状态变化。`both` 使用连续两分钟的上下班提醒；`background` 使用相同时间但启动时不打开设置。
